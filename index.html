Philosophical Core

Like the Zen concept of Ma (negative space) and Wabi-Sabi (transience), application state should exist cleanly, without excess middleware or convoluted hooks.

現

Cells (Reality)

The smallest unit of atomic state. Simple leaf nodes holding the absolute truth, avoiding proxies and obscure subscriptions.

鏡

Lenses (Reflections)

Read-only derived states that evaluate once and cache. They wake up when components mount, and sleep when they unmount.

意

Intents (Conscious Change)

Pure functions that state the direction of update. No implicit drift; state transitions strictly via named, testable intents.

枠

Frames (Boundaries)

Create transactional boundaries for multiple updates. UI re-renders exactly once when the frame closes. Zero layout thrashing.

Utsutsu Manual

Comprehensive, professional guide for building high-performance React applications with Utsutsu.

1. Philosophy & Core

Traditional state management packages often force developers into one of two extremes:

  • The Redux/Zustand Trap: A single global state tree. Hooks subscribe to selectors. If selectors are not written with intense care (or wrapped in memoization layers like Reselect), any slight state change triggers massive, unnecessary React re-renders.
  • The Signal Trap: Proxy-based magic. State mutation happens implicitly by assignment (`state.count++`), leading to difficult debugging, lost action traceability, and code that drifts away from pure react guidelines.

Utsutsu bridges this gap. It is built around traditional Japanese design concepts: keeping definitions clean, making updates explicit, and letting the framework handle dependencies automatically.

Zen Axiom: Explicit Mutations

State in Utsutsu cannot change by accident. It is read-only at the view level and only updates through named intents.

2. Getting Started

Install the library via NPM or Yarn:

npm install utsutsu

Here is a complete, minimal example of setting up a counter application in React:


import React from "react";
import { createUtsutsu, useValue } from "utsutsu";

// 1. Create the store
const store = createUtsutsu({ count: 0 });

// 2. Define a Lens (derived selector)
const countLens = store.lens("count", state => state.count);

// 3. Define an Intent (update)
const increment = store.intent("increment", state => ({
  ...state,
  count: state.count + 1
}));

// 4. Connect to React
export function Counter() {
  const count = useValue(countLens);
  return (
    <button onClick={increment}>
      Count: {count}
    </button>
  );
}

3. State Cells (Atoms)

Cells are the writeable leaf nodes of your state graph. When you initialize a store via `createUtsutsu`, you define a single, unified source of truth. Utsutsu decomposes this state object into individual Cells behind the scenes.

Crucially, Cells do not trigger re-renders unless a component explicitly subscribes to them via a Lens. This separates data layout from re-render concerns.

Cell Guidelines

Keep your initial state schema flat where possible. Deeply nested objects make intent reducers more verbose and make dynamic key targeting harder to track.

4. Lenses (Derived State)

Lenses are read-only windows into your Cells. A lens takes a path name and a selector function, computes the derived state, and caches the result.


// Basic selector lens
const userLens = store.lens("user", s => s.user.profile);

// Complex derived state lens
const activeTodosLens = store.lens("activeTodos", s => {
  return s.todos.filter(t => !t.completed);
});

Caching and Evaluation Graph

Utsutsu builds a directed acyclic graph (DAG) of your lenses. If a Lens depends on two separate cells, it will only recompute if one of those cell values changes. If a component subscribes to `activeTodosLens`, it will **only** re-render if the final list array reference actually changes, preventing wasteful updates.

5. Intents (Updates)

Intents are conscious actions taken by the user or the system. They are equivalent to Redux action creators and reducers rolled into one single, type-safe definition.


// Simple state modifier intent
const setUsername = store.intent("setUsername", (state, newName: string) => ({
  ...state,
  user: { ...state.user, name: newName }
}));

// Usage in event handler
<input onChange={e => setUsername(e.target.value)} />

Asynchronous Actions

Since intents must remain pure synchronous state transformers, handle side effects (like fetch requests) using regular functions that dispatch intents when they resolve:


// Async side-effect handler
async function fetchUser(userId: string) {
  const res = await fetch(`/api/users/${userId}`);
  const data = await res.json();
  // Dispatch pure intent
  setUsername(data.username);
}

6. Frames (Transactions)

In highly interactive UIs, you may need to update multiple values in sequence. Doing this sequentially normally causes React to batch updates inside react scope, but it can trigger multiple internal store subscriptions and transient values.

Utsutsu solves this via **Frames**—transactional boundaries for state manipulation.


import { frame } from "utsutsu";

// Group multiple operations into a single tick
frame(() => {
  increment();
  calmPond();
  logActivity();
}); // Subscribers are notified EXACTLY once here when the frame closes.

7. React Integration

Utsutsu provides two core React hooks:

  • useValue(lens): Subscribes a component to a Lens. Returns the current cached selector value.
  • useIntent(intent): Binds an intent to a component's lifecycle (optional, as intents can also be called globally).

Performance Example

Here, even if `store.state.logs` updates 100 times per second, `UserInfo` will not re-render, because it is only subscribed to `userLens`:


function UserInfo() {
  const user = useValue(userLens); // Surgical subscriber
  return <div>Welcome, {user.name}</div>;
}

8. DevTools & Debugging

Utsutsu features out-of-the-box support for the Redux DevTools extension, letting you travel back in time, inspect action payloads, and debug state changes visually.


import { connectDevTools } from "utsutsu/devtools";

const store = createUtsutsu({ count: 0 });
connectDevTools(store, { name: "Zen Store Preview" });

9. API Reference

The full TypeScript API definitions for Utsutsu's core functions:

createUtsutsu<T>(initialState: T): UtsutsuStore<T>

Creates a new state container instance.

store.lens<V>(name: string, selector: (state: T) => V): Lens<V>

Creates a selector lens with custom caching and dependency tracking.

store.intent<A extends any[]>(name: string, mutator: (state: T, ...args: A) => T): (...args: A) => void

Creates an intent function. Modifies the store state synchronously using pure reducer logic.

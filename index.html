Architectural Pillars

Utsutsu (現) translates to "the waking world." We keep state transparent, updates traceably explicit, and re-renders surgically minimal.

Cells (Reality)

Atomic, readable state values. Simple leaf elements of truth that bypass heavy proxy observation systems.

Lenses (Reflections)

Cached derived state nodes that automatically track dependencies. They wake up on mount and sleep on unmount.

Intents (Conscious Actions)

Pure state transactions. State doesn't shift implicitly; it transitions strictly via named, trace-ready intents.

Frames (Boundaries)

Create transactional batch boundaries. UI re-renders exactly once when the frame exits. Zero lay-out flickering.

Utsutsu Guidebook

Complete multi-scenario architectural guides and strict API specifications.

1. Philosophy & Installation

Utsutsu (現) stands for "consciousness" and "reality". We believe React state libraries should be simple to write, explicit to update, and precise to re-render.

Most frameworks force you into selector boilerplate (Zustand selectors, Redux Reselect) or proxy implicit mutations (Signals assignment). Utsutsu offers the best of both: synchronous, trace-ready unidirectional updates wrapped in automatically cached, dynamic dependency selector trees.

Installation

npm install utsutsu

Utsutsu has zero dependencies, and bundles to under 1.5kB (minified + gzipped), fully supporting Concurrent Features in React 18+.

2. Core Concepts

Utsutsu's architecture rests on four simple elements:

  • Cells: Writable units of state. The atoms of application reality.
  • Lenses: Read-only derived values. Lenses form a dependency graph, computing evaluations lazily and caching results until their underlying dependency cells update.
  • Intents: Pure state mutations. Reducers and actions rolled into a single named function.
  • Frames: Group multiple state mutations within a single transaction boundary, ensuring React only receives a single combined notify pulse at the end.

import { createUtsutsu } from "utsutsu";

const store = createUtsutsu({
  username: "Rimuru",
  power: 9000
});

// A Lens tracks state changes and caches
const powerStatusLens = store.lens("powerStatus", s => ({
  name: s.username,
  isOver9000: s.power > 9000
}));

// An Intent declares how state updates
const train = store.intent("train", (state, amount: number) => ({
  ...state,
  power: state.power + amount
}));

3. Scenario: Global Shopping Cart

This scenario shows how to manage a shopping cart with dynamic calculations (subtotal, taxes, discounts) that must compute instantly without wasteful render triggers in product lists.


import { createUtsutsu, useValue } from "utsutsu";

// 1. Define State Interfaces
interface CartItem { id: string; name: string; price: number; qty: number; }
interface CartState { items: CartItem[]; couponDiscount: number; taxRate: number; }

const store = createUtsutsu<CartState>({
  items: [],
  couponDiscount: 0.15, // 15% discount
  taxRate: 0.08        // 8% tax
});

// 2. Computed Lenses (Derived state caches automatically)
export const cartItemsLens = store.lens("items", s => s.items);

export const cartSubtotalLens = store.lens("subtotal", s => 
  s.items.reduce((sum, item) => sum + (item.price * item.qty), 0)
);

export const cartTotalLens = store.lens("total", s => {
  // Lenses can depend on other computed fields/properties
  const subtotal = s.items.reduce((sum, item) => sum + (item.price * item.qty), 0);
  const discounted = subtotal * (1 - s.couponDiscount);
  return discounted * (1 + s.taxRate);
});

// 3. Waking Intents (Synchronous State Transitions)
export const addToCart = store.intent("addItem", (s, newItem: CartItem) => {
  const existingIndex = s.items.findIndex(item => item.id === newItem.id);
  if (existingIndex > -1) {
    const updatedItems = [...s.items];
    updatedItems[existingIndex].qty += 1;
    return { ...s, items: updatedItems };
  }
  return { ...s, items: [...s.items, newItem] };
});

export const updateQty = store.intent("updateQty", (s, id: string, qty: number) => ({
  ...s,
  items: s.items.map(item => item.id === id ? { ...item, qty } : item).filter(item => item.qty > 0)
}));

// 4. React Integration (Subscribes surgically to target slices)
export function CartSummary() {
  const subtotal = useValue(cartSubtotalLens);
  const total = useValue(cartTotalLens);

  return (
    <div className="cart-checkout">
      <div>Subtotal: ${subtotal.toFixed(2)}</div>
      <div>Grand Total: ${total.toFixed(2)}</div>
    </div>
  );
}

4. Scenario: RPG Battle System (Batched Actions)

This scenario shows how to handle complex nested state and dynamic battle actions, using Frames to batch character turns into a single UI update.


import { createUtsutsu, useValue, frame } from "utsutsu";

interface Character { name: string; hp: number; maxHp: number; mana: number; }
interface BattleState { party: Character[]; turnIndex: number; combatLog: string[]; }

const store = createUtsutsu<BattleState>({
  party: [
    { name: "Rimuru Tempest", hp: 1200, maxHp: 1500, mana: 85 },
    { name: "Megumin", hp: 600, maxHp: 800, mana: 50 }
  ],
  turnIndex: 0,
  combatLog: ["Battle commenced."]
});

// Lenses
export const partyLens = store.lens("party", s => s.party);
export const activeLogLens = store.lens("logs", s => s.combatLog);

// Intents
export const damageHero = store.intent("damageHero", (s, index: number, damage: number) => {
  const updatedParty = [...s.party];
  updatedParty[index] = {
    ...updatedParty[index],
    hp: Math.max(0, updatedParty[index].hp - damage)
  };
  return { ...s, party: updatedParty };
});

export const consumeMana = store.intent("useMana", (s, index: number, amount: number) => {
  const updatedParty = [...s.party];
  updatedParty[index] = {
    ...updatedParty[index],
    mana: Math.max(0, updatedParty[index].mana - amount)
  };
  return { ...s, party: updatedParty };
});

export const addLog = store.intent("addLog", (s, message: string) => ({
  ...s,
  combatLog: [...s.combatLog, message]
}));

// Multi-Action Batch: Frame execution
export function executeSpellRound() {
  // Megumin casts Explosion! Groups multiple intents into a single transaction frame.
  // Component subscriptions receive exactly one notification tick, avoiding layout thrashing.
  frame(() => {
    consumeMana(1, 40);             // Megumin loses mana
    damageHero(1, 50);              // Recoil damage to Megumin
    addLog("Megumin cast Explosion!"); // Add combat log entry
  });
}

5. Scenario: Form Validation & Debounced Autosave

This scenario shows how to validate user forms in real-time using computed lenses, and handle debounced asynchronous autosaves using Intents.


import { createUtsutsu, useValue } from "utsutsu";

interface FormState {
  fields: { email: string; name: string; age: number; };
  status: "idle" | "saving" | "saved" | "error";
}

const store = createUtsutsu<FormState>({
  fields: { email: "", name: "", age: 18 },
  status: "idle"
});

// Derived validation Lenses (Evaluated once, cached)
export const emailErrorLens = store.lens("emailErr", s => {
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  if (!s.fields.email) return "Email is required.";
  if (!emailRegex.test(s.fields.email)) return "Invalid email address format.";
  return null;
});

export const isFormValidLens = store.lens("isValid", s => {
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return s.fields.name.length >= 2 && emailRegex.test(s.fields.email);
});

// Intents
export const updateField = store.intent("setField", (s, key: "email" | "name", val: string) => ({
  ...s,
  fields: { ...s.fields, [key]: val }
}));

export const setSavingStatus = store.intent("setStatus", (s, status: FormState["status"]) => ({
  ...s,
  status
}));

// Asynchronous side-effect helper with debounce
let saveTimeout: ReturnType<typeof setTimeout>;
export function triggerAutosave(formData: FormState["fields"]) {
  setSavingStatus("saving");
  clearTimeout(saveTimeout);
  
  saveTimeout = setTimeout(async () => {
    try {
      await fetch("/api/save-form", {
        method: "POST",
        body: JSON.stringify(formData)
      });
      setSavingStatus("saved");
    } catch {
      setSavingStatus("error");
    }
  }, 1000);
}

6. Strict API Specification

Detailed TypeScript type declarations and parameter definitions for Utsutsu's public exports.

1. createUtsutsu


function createUtsutsu<T extends object>(initialState: T): UtsutsuStore<T>;

interface UtsutsuStore<T> {
  // Access raw, unwraped current state snapshot
  state: T;
  
  // Creates a derived cache lens
  lens<V>(name: string, selector: (state: T) => V): Lens<V>;
  
  // Creates a synchronous state modifier intent
  intent<Args extends any[]>(
    name: string, 
    mutator: (state: T, ...args: Args) => T
  ): (...args: Args) => void;
  
  // Subscribe to raw changes (useful for integrations)
  subscribe(listener: () => void): () => void;
}

2. useValue


// React Hook. Subscribes component to a Lens. Rerenders ONLY when value changes.
function useValue<V>(lens: Lens<V>): V;

3. frame


// Batches multiple operations into a single tick
function frame(callback: () => void): void;

1. Motivation & Philosophy

Why create Utsutsu when we have Redux, Zustand, Recoil, and Signals? State management in modern React typically falls into two traps:

The Selector Trap (Zustand/Redux)

In store libraries, you pull values via selector functions:

const count = useStore(state => state.counters[id].value);

If you don't write selectors with extreme care, or if you select an object instead of a primitive, **React will re-render your component on every single state change anywhere in the store**. This leads to manual optimizations (e.g. `useShallow`, `createSelector` from Reselect), which add clutter and cognitive load.

The Magic Proxy Trap (Signals/MobX)

Signals solve re-render issues by using proxy wrapper objects and intercepting property access:

state.count++; // Implicit modification

While this is highly performant, it bypasses React's unidirectional data flow rules. State mutations happen implicitly anywhere in your views, making bug tracing, time-travel debugging, and test assertions extremely difficult. It also runs counter to React 18 Concurrent Rendering patterns.

The Waking World Solution: Utsutsu (現)

Utsutsu offers a third way: state is read-only in components, updates are dispatched via named pure mutators (Intents), and components subscribe to Lenses. Lenses compile into a dynamic evaluation graph, recalculating lazily and surgically notifying only the exact components that rely on modified dependencies.

2. Getting Started

Add Utsutsu to your project using your package manager of choice:


# npm
npm install utsutsu
# yarn
yarn add utsutsu
# pnpm
pnpm add utsutsu

Setting up Utsutsu requires three simple steps: defining your initial state, creating computed lenses for reading, and declaring intents for updates.


import { createUtsutsu } from "utsutsu";

// 1. Create a global state slice
export const store = createUtsutsu({
  count: 0,
  username: "Rimuru"
});

// 2. Define computed lenses outside of React components
export const countLens = store.lens("count", s => s.count);

// 3. Declare intents for updating
export const increment = store.intent("increment", (state, amount: number = 1) => ({
  ...state,
  count: state.count + amount
}));

Then, connect the lens inside a React component using the `useValue` hook:


import React from "react";
import { useValue } from "utsutsu";
import { countLens, increment } from "./store";

export function Counter() {
  const count = useValue(countLens);
  return (
    <button onClick={() => increment(1)}>
      Count is: {count}
    </button>
  );
}

3. Cells (Atomic State)

Behind the scenes, when you initialize a store with a state shape, Utsutsu decomposes the state into writeable reactive units called **Cells**.

A Cell acts as a single leaf node in your reactive graph. It holds the absolute raw value and maintains an integer version counter. When an intent updates a cell, the version counter increments. This informs child derived nodes that their cached evaluations are out of date.

Granularity Guideline

Do not create separate stores for every primitive value. Create a unified store slice representing a distinct business domain (e.g. `authStore`, `shoppingStore`) and let Utsutsu decompose them into atomic cells automatically.

4. Lenses (Derived Cache)

Lenses are read-only derived state nodes. They map a slice of your cells to a computed value:


const activeItemsLens = store.lens("active", state => 
  state.items.filter(item => item.active)
);

Dynamic Dependency Tracking & Lazy Evaluation

When a Lens executes, Utsutsu intercepts all cell read operations and dynamically records the cell keys as dependencies. If cell values do not change, the Lens returns the cached result, bypassing the selector logic.

Furthermore, if a component is unmounted, Utsutsu automatically puts its subscribed lenses to sleep, suspending evaluation runs until another active component requests them. This prevents memory leaks and background computational waste.

5. Intents (Explicit Updates)

Intents represent deliberate state updates. Unlike Redux where actions and reducers are defined separately, Utsutsu defines them together in a single, type-safe definition:


export const changeUsername = store.intent("setName", (state, name: string) => ({
  ...state,
  username: name
}));

Handling Side Effects

Intents must remain pure, synchronous state transformers. For asynchronous processes (like API calls), handle the async operation in a standard function and call the intent when the promise resolves:


export async function loadUserProfile(userId: string) {
  try {
    const res = await fetch(`/api/users/${userId}`);
    const profile = await res.json();
    // Dispatch pure intent
    changeUsername(profile.username);
  } catch (err) {
    console.error("Failed to load user profile", err);
  }
}

6. Frames (Transactions)

If you call multiple intents sequentially, each call ordinarily fires a store notification pulse. If these calls occur outside of React event handlers, it can result in multiple unnecessary UI render passes.

Utsutsu resolves this through **Frames**—transactional update boundaries.


import { frame } from "utsutsu";

function resetGame() {
  frame(() => {
    resetScore();
    clearBoard();
    incrementMatchCount();
  }); // React is notified exactly once here
}

7. React Integration

Utsutsu integrates with React using `useSyncExternalStore` under the hood. This guarantees that your components remain fully synchronized with the store, eliminating "tearing" during React 18 concurrent transitions.

Precision Re-rendering

Because components subscribe directly to Lenses, a component will **only** re-render if the final evaluated lens reference changes. If a sibling cell changes, the component's render hook is never triggered, enabling near-native re-rendering performance.

Recipe A: Shopping Cart

This recipe demonstrates how to calculate subtotal, discount codes, and taxes dynamically using cached lenses without causing re-renders in other sections of the catalog.


import { createUtsutsu, useValue } from "utsutsu";

interface CartItem { id: string; name: string; price: number; qty: number; }
interface CartState { items: CartItem[]; discount: number; tax: number; }

const store = createUtsutsu<CartState>({
  items: [],
  discount: 0.1, // 10% discount
  tax: 0.08      // 8% tax rate
});

// Lenses (Derived Caches)
export const itemsLens = store.lens("items", s => s.items);

export const subtotalLens = store.lens("subtotal", s => 
  s.items.reduce((sum, item) => sum + (item.price * item.qty), 0)
);

export const grandTotalLens = store.lens("grandTotal", s => {
  const sub = s.items.reduce((sum, item) => sum + (item.price * item.qty), 0);
  const discountedSub = sub * (1 - s.discount);
  return discountedSub * (1 + s.tax);
});

// Intents
export const addItem = store.intent("add", (s, item: CartItem) => {
  const index = s.items.findIndex(i => i.id === item.id);
  if (index > -1) {
    const updated = [...s.items];
    updated[index].qty += 1;
    return { ...s, items: updated };
  }
  return { ...s, items: [...s.items, item] };
});

export const removeOne = store.intent("remove", (s, id: string) => ({
  ...s,
  items: s.items.map(i => i.id === id ? { ...i, qty: i.qty - 1 } : i).filter(i => i.qty > 0)
}));

Recipe B: RPG Party Battle HUD

This recipe coordinates stats for multiple party members, showing how to execute spell turns and log events inside a single transaction frame.


import { createUtsutsu, frame } from "utsutsu";

interface Hero { name: string; hp: number; mp: number; status: string; }
interface BattleState { squad: Hero[]; battleLog: string[]; }

const store = createUtsutsu<BattleState>({
  squad: [
    { name: "Rimuru Tempest", hp: 1500, mp: 90, status: "Normal" },
    { name: "Megumin", hp: 700, mp: 60, status: "Normal" }
  ],
  battleLog: []
});

// Intents
export const damageHero = store.intent("damage", (s, index: number, hpLoss: number) => {
  const squad = [...s.squad];
  squad[index] = { ...squad[index], hp: Math.max(0, squad[index].hp - hpLoss) };
  return { ...s, squad };
});

export const useMana = store.intent("spendMp", (s, index: number, mpLoss: number) => {
  const squad = [...s.squad];
  squad[index] = { ...squad[index], mp: Math.max(0, squad[index].mp - mpLoss) };
  return { ...s, squad };
});

export const writeLog = store.intent("log", (s, msg: string) => ({
  ...s,
  battleLog: [...s.battleLog, msg]
}));

// Coordinated Round execution
export function executeSpellRound() {
  frame(() => {
    useMana(1, 30);
    damageHero(1, 100);
    writeLog("Megumin cast spell, losing HP & Mana!");
  }); // All subscribers are notified once
}

Recipe C: Form Validation

Autosave input values, calculate error messages on-demand using cached lenses, and trigger async validations.


import { createUtsutsu } from "utsutsu";

const store = createUtsutsu({
  email: "",
  password: "",
  loading: false
});

// Lenses for instant validation feedback
export const isEmailValidLens = store.lens("emailVal", s => {
  const regex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return regex.test(s.email);
});

export const formErrorLens = store.lens("errors", s => {
  if (s.password.length > 0 && s.password.length < 8) {
    return "Password must be at least 8 characters.";
  }
  return null;
});

// Intents
export const setField = store.intent("setField", (s, key: "email" | "password", value: string) => ({
  ...s,
  [key]: value
}));

Recipe D: LocalStorage Middleware

A complete middleware implementation that automatically persists state changes to `localStorage` and restores them on page reload.


import { createUtsutsu } from "utsutsu";

export function createPersistentStore<T extends object>(key: string, defaultState: T) {
  // 1. Read existing cache
  const cached = localStorage.getItem(key);
  const initialState = cached ? JSON.parse(cached) : defaultState;

  // 2. Create the store instance
  const store = createUtsutsu<T>(initialState);

  // 3. Listen for changes and write back to storage
  store.subscribe(() => {
    localStorage.setItem(key, JSON.stringify(store.state));
  });

  return store;
}

// Usage
const userStore = createPersistentStore("app-user-session", {
  token: "",
  loggedIn: false
});

Core API Exports

Type declarations and parameters for all exported Utsutsu library utilities.

createUtsutsu<T>(initialState: T): UtsutsuStore<T>

Initializes a new state store instance.


interface UtsutsuStore<T> {
  state: T;
  
  // Define derived cache lens
  lens<V>(name: string, selector: (state: T) => V): Lens<V>;
  
  // Define update intent
  intent<A extends any[]>(
    name: string, 
    mutator: (state: T, ...args: A) => T
  ): (...args: A) => void;
  
  // Subscribe listener to state updates
  subscribe(listener: () => void): () => void;
}

useValue<V>(lens: Lens<V>): V

React hook. Subscribes component to a computed Lens, executing local re-renders ONLY when the returned reference updates.

frame(callback: () => void): void

Transactional boundary tool. Holds component triggers inside the callback block and notifies subscribers once at the end.

Under the Hood: Evaluation Graph

Utsutsu operates on a directed acyclic graph (DAG) model to prevent redundant derived calculations. It utilizes the following components:

Dynamic Evaluation Stack

A global array of active lenses is maintained during the read phase. When a Lens selector runs, it pushes itself onto the stack. Any Cell read operations query the top of the stack and register the Lens as a subscriber.

Version Tracking

To bypass string/array comparison overhead, every Cell maintains an integer version counter. Lenses cache the cell versions used in their last evaluation. If the cell versions match, the cached value is returned immediately. This ensures $O(1)$ cache hit resolution.
